# MyShows Scrobble API

Скробблинг — это отметка просмотра в реальном времени. Плеер сообщает MyShows, что
пользователь начал смотреть, где он сейчас находится и когда досмотрел. Пользователю
не нужно ничего отмечать руками.

API рассчитан на сторонних разработчиков: плееры, плагины, медиасерверы, мобильные
клиенты. Формат запроса — надмножество scrobble-API Trakt и Simkl, поэтому один payload
можно отправлять во все три сервиса без изменений.

> **Референс-реализация.** [MyShows Scrobbler](https://github.com/MyShowsMe/myshows-scrobbler) —
> открытый клиент, который работает с этим API. Полезен как рабочий пример: сборка
> payload — в [`src/scrobblers/converter.ts`](../../src/scrobblers/converter.ts),
> HTTP-слой — в [`src/scrobblers/myshows.ts`](../../src/scrobblers/myshows.ts),
> типы DTO — в [`src/scrobblers/scrobble-dto.ts`](../../src/scrobblers/scrobble-dto.ts).

## Быстрый старт

Возьмите токен в [профиле](https://myshows.me/profile/watch-history/), проверьте его и
отправьте первый скробл.

```bash
# 1. Проверяем токен
curl https://myshows.me/scrobble/check \
  -H "Authorization: Bearer $MYSHOWS_TOKEN"

# 2. Пользователь начал смотреть эпизод
curl https://myshows.me/scrobble/start \
  -H "Authorization: Bearer $MYSHOWS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "progress": 2.5,
    "source_app": "my-player",
    "show":    { "title": "Severance", "year": 2022, "ids": { "imdb": "tt11280740" } },
    "episode": { "season": 2, "number": 1 }
  }'

# 3. Пользователь досмотрел — отмечаем просмотр
curl https://myshows.me/scrobble/stop \
  -H "Authorization: Bearer $MYSHOWS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "progress": 92.0,
    "source_app": "my-player",
    "show":    { "title": "Severance", "year": 2022, "ids": { "imdb": "tt11280740" } },
    "episode": { "season": 2, "number": 1 }
  }'
```

Всё. Эпизод отмечен просмотренным в профиле пользователя.

## Аутентификация

Каждый запрос требует заголовка `Authorization` с персональным токеном пользователя:

```http
Authorization: Bearer <token>
```

Токен пользователь берёт сам на странице
[профиля](https://myshows.me/profile/watch-history/) и вставляет в ваше приложение.
Токен привязан к аккаунту и не истекает по времени.

**Требования к обработке токена:**

- Токен состоит только из ASCII-символов. Проверяйте это перед отправкой — так вы
  поймаете случай, когда пользователь скопировал текст с кириллическими символами и
  получил бы невнятную ошибку транспорта вместо понятного сообщения.
- Не логируйте токен и не показывайте его в UI после сохранения. Референс-клиент
  маскирует его при чтении конфигурации.
- В клиент-серверных приложениях храните токен на своей стороне и не отдавайте его в
  браузер.

## Как работает скробблинг

Три эндпоинта описывают жизненный цикл одного просмотра.

| Событие у вас | Эндпоинт | Что делает MyShows |
|---|---|---|
| Пользователь начал смотреть | `POST /start` | открывает сессию просмотра |
| Пользователь продолжает / поставил на паузу | `POST /pause` | обновляет позицию |
| Пользователь досмотрел | `POST /stop` | закрывает сессию и **отмечает просмотр** |

Ключевое: просмотр засчитывается на `/stop`, и только если `progress` достаточно высок.

**Порог отметки.** Считайте просмотр состоявшимся начиная с 80% — это значение по
умолчанию в референс-клиенте, и оно совпадает с порогом Trakt и Simkl. Разумный диапазон
для пользовательской настройки — 50–95%. Если пользователь бросил просмотр раньше порога,
`/stop` слать не нужно вовсе: сессия закроется сама.

**Рекомендуемый цикл:**

1. Начало воспроизведения → `POST /start` с текущим `progress`.
2. Дальше раз в 10–30 секунд → `POST /pause` с обновлённым `progress`.
   Не шлите запрос, если прогресс не сдвинулся с прошлого раза — референс-клиент
   пропускает такие тики. При перемотке и паузе шлите `/pause` сразу, вне расписания.
3. Прогресс перешёл порог → `POST /stop`. Дальше по этой сессии не шлите ничего.
4. Воспроизведение прервано до порога → не шлите ничего.

Если `/stop` не прошёл из-за сети — не считайте сессию закрытой. Продолжайте слать
`/pause` и попробуйте `/stop` на следующем тике. Так сетевой сбой не съедает отметку.

## Эндпоинты

Базовый URL: `https://myshows.me/scrobble`

### `GET /check`

Проверяет токен. Вызывайте при вводе токена пользователем, чтобы сразу показать, принят
он или нет.

```bash
curl https://myshows.me/scrobble/check -H "Authorization: Bearer $TOKEN"
```

<!-- УТОЧНИТЬ (бэкенд): что именно возвращает /check в теле ответа. Референс-клиент
     смотрит только на HTTP-статус и тело не парсит. Если там есть логин/ID/лимиты —
     это стоит задокументировать, приложения смогут показать «вы вошли как …». -->

### `POST /start`

Открывает сессию просмотра. Тело — [объект запроса](#тело-запроса).

### `POST /pause`

Обновляет позицию в открытой сессии. Тело — то же самое, меняется только `progress`.

### `POST /stop`

Закрывает сессию. Если `progress` выше порога, просмотр отмечается в профиле.

Все три принимают одинаковое тело и возвращают одинаковый
[объект ответа](#тело-ответа).

## Тело запроса

Два варианта: фильм или эпизод сериала.

**Фильм** — объект `movie`:

```json
{
  "progress": 45.2,
  "source_app": "my-player",
  "app_version": "1.4.0",
  "movie": {
    "title": "Dune: Part Two",
    "original_title": "Dune: Part Two",
    "year": 2024,
    "runtime": 166,
    "content_rating": "PG-13",
    "ids": { "imdb": "tt15239678", "tmdb": "693134" },
    "metadata": {
      "resolution": "uhd_4k",
      "hdr": "dolby_vision",
      "audio": "dolby_atmos",
      "audio_channels": "7.1",
      "audio_language": "en"
    }
  }
}
```

**Эпизод** — пара объектов `show` + `episode`:

```json
{
  "progress": 45.2,
  "source_app": "my-player",
  "dub_team": "AniLibria",
  "show": {
    "title": "Frieren: Beyond Journey's End",
    "original_title": "葬送のフリーレン",
    "year": 2023,
    "ids": { "imdb": "tt22248376", "shikimori": 52991 }
  },
  "episode": {
    "season": 1,
    "number": 12,
    "title": "A Real Hero",
    "runtime": 24,
    "metadata": { "resolution": "hd_1080p", "audio_language": "ja" }
  }
}
```

### Общие поля

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `progress` | number | **да** | Прогресс в процентах, 0.0–100.0 |
| `app_version` | string | нет | Версия вашего приложения |
| `app_date` | string | нет | Дата сборки, `YYYY-MM-DD` |
| `source_app` | string | нет | Идентификатор источника: `"plex"`, `"kodi"`, `"lampa"`, `"browser"` |
| `dub_team` | string | нет | Студия озвучки: `"AniLibria"`, `"Кубик в Кубе"` |
| `rating` | number | нет | Оценка пользователя 1–10. Обычно отправляется вместе с `/stop` |

`source_app`, `dub_team` и `rating` — расширения MyShows. Trakt и Simkl их игнорируют,
так что наличие этих полей не мешает отправить тот же payload туда.

| Поле | Тип | Описание |

## Аниме

Аниме — единственная категория, где номер эпизода неоднозначен сам по себе, поэтому
правил для неё чуть больше.

### Какие идентификаторы слать

Кроме общих ключей есть пять аниме-специфичных: `anidb`, `anilist`, `kitsu`, `mal`,
`shikimori`. Если знаете хоть один — отправляйте. Для аниме они надёжнее `tmdb` и `tvdb`,
потому что не зависят от того, как каталог нарезал сериал на сезоны.

Если знаете и `tmdb`, и `tvdb` — отправляйте **оба**. На сплит-кур тайтлах (Attack on
Titan, Solo Leveling) границы сезонов у этих двух каталогов расходятся, и по одному ID
невозможно понять, о каком куске сериала речь.

<!-- УТОЧНИТЬ (бэкенд): какой идентификатор выигрывает при конфликте TMDB и TVDB.
     У Simkl маппинг построен на координатах TVDB, и правило зафиксировано явно.
     Нам нужно такое же: без него сплит-кур аниме уедет не в тот тайтл — молча. -->

### Абсолютная нумерация

У аниме-релизов сезон часто просто отсутствует: в имени файла стоит сквозной номер —
`Frieren - 12 [1080p].mkv`. В этом случае отправляйте `episode.number` без
`episode.season`. Это допустимо, поле необязательное.

**Не пересчитывайте абсолютный номер в пару «сезон + эпизод» на своей стороне.** Для
этого нужна та же таблица маппинга, что и у каталога, а разъедется она незаметно и
задним числом. Отправьте то, что знаете, и оставьте сопоставление серверу.

Референс-клиент так и устроен: парсер имени файла достаёт сквозной номер и оставляет
сезон пустым ([`filename-parser.ts`](../../src/utils/filename-parser.ts)), а конвертер
просто не кладёт поле в payload ([`converter.ts`](../../src/scrobblers/converter.ts)).

### Спецвыпуски, OVA и ONA

Референс-клиент их не различает: OVA уходит эпизодом родительского сериала с тем
номером, который дал источник.

## Тело ответа

```json
{
  "id": 184756,
  "action": "scrobble",
  "progress": 92.0,
  "watched_at": "2026-08-16T19:24:11Z",
  "show":    { "title": "Severance", "year": 2022, "ids": { "imdb": "tt11280740" } },
  "episode": { "season": 2, "number": 1 }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `id` | number | ID записи о воспроизведении |
| `action` | enum | `start` · `pause` · `scrobble` · `checkin` |
| `progress` | number | Прогресс, который зафиксировал сервер |
| `watched_at` | string | ISO 8601, когда отмечен просмотр. Приходит при `action: "scrobble"` |
| `expires_at` | string | ISO 8601, когда истекает сессия |
| `movie` / `show` + `episode` | object | Тайтл в том виде, в каком его распознал MyShows |

Возвращённый объект тайтла полезен для сверки: если MyShows распознал не то, что вы
отправили, это видно сразу.

## Ошибки

<!-- УТОЧНИТЬ (бэкенд): полная таблица кодов и формат тела ошибки.
     Ниже — то, что видно со стороны клиента; это не спецификация. -->

Сейчас со стороны клиента различимы:

| Код | Значение |
|---|---|
| `401` | Токен неверен или отозван — попросите пользователя обновить его |
| `4xx` | Ошибка в запросе; повторять бессмысленно |
| `5xx` | Ошибка сервера; повторять можно |

Формат тела ошибки не зафиксирован — референс-клиент показывает его как есть.

**Повторы.** На сетевых ошибках и `5xx` делайте до трёх попыток с экспоненциальной
паузой (1 с, 2 с). Таймаут запроса — 5 секунд. На `4xx` не повторяйте.

## Правила использования

<!-- УТОЧНИТЬ (бэкенд): rate limits в запросах за единицу времени, поведение при
     превышении (429 + Retry-After?), политика для приложений с большой базой
     пользователей. У Simkl это первый экран страницы правил — цифра нужна. -->

Пока лимиты не опубликованы, придерживайтесь этих правил — они удерживают трафик на
разумном уровне сами по себе:

- **Не чаще одного `/pause` в 10 секунд** на активную сессию.
- **Пропускайте тики без движения.** Если `progress` не изменился с прошлой отправки,
  запрос не нужен.
- **Указывайте `source_app` и `app_version`.** Это единственный способ для MyShows
  отличить трафик вашего приложения от чужого — в том числе когда нужно разобраться с
  проблемой, а не заблокировать.
- **Не полируйте прогресс.** Отправляйте то, что реально говорит плеер.

## Совместимость с Trakt и Simkl

Формат специально сделан надмножеством scrobble-API Trakt и Simkl: и Trakt, и Simkl
игнорируют неизвестные поля, поэтому один и тот же payload уходит во все три сервиса без
изменений. Если вы уже интегрированы с Trakt или Simkl, поддержка MyShows — это новый
базовый URL и токен, а не новый маппинг.

| Поле | MyShows | Trakt | Simkl |
|---|---|---|---|
| `progress`, `movie`, `show`, `episode` | ✅ | ✅ | ✅ |
| `app_version`, `app_date` | ✅ | ✅ | ✅ |
| `ids.imdb`, `ids.tmdb`, `ids.tvdb`, `ids.slug` | ✅ | ✅ | ✅ |
| `ids.anidb`, `ids.mal`, `ids.netflix`, `ids.hulu` | ✅ | — | ✅ |
| `ids.shikimori`, `ids.kinopoisk`, `ids.anilist`, `ids.kitsu` | ✅ | — | — |
| `metadata.*` | ✅ | ✅ (в `/sync/collection`) | — |
| `source_app`, `dub_team`, `rating` | ✅ | — | — |
| `original_title`, `content_rating`, `runtime` | ✅ | — | — |

Одно известное расхождение типов: `ids.tmdb` у Trakt объявлен как number, у Simkl — как
string. На практике оба принимают строку, поэтому в этом API тип — **string**.
