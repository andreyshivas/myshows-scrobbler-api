Справочник API

Scrobble API

Скробблинг — это отметка просмотра в реальном времени. Плеер сообщает MyShows, что пользователь начал смотреть, где он сейчас и когда досмотрел. Пользователю не нужно отмечать ничего руками.

API рассчитан на сторонних разработчиков: плееры, плагины, медиасерверы, мобильные клиенты. Формат запроса — надмножество scrobble-API Trakt и Simkl, поэтому один payload уходит во все три сервиса без изменений.

Референс-реализация

MyShows Scrobbler — открытый клиент этого API. Сборка payload — src/scrobblers/converter.ts, HTTP-слой — src/scrobblers/myshows.ts, типы — src/scrobblers/scrobble-dto.ts.

Быстрый старт

Возьмите токен в профиле, проверьте его и отправьте первый скробл.

bash
# 1. Проверяем токен
curl https://myshows.me/scrobble/check \
  -H "Authorization: Bearer $MYSHOWS_TOKEN"

# 2. Пользователь начал смотреть эпизод
curl https://myshows.me/scrobble/start \
  -H "Authorization: Bearer $MYSHOWS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "progress": 2.5,
    "source_app": "my-player",
    "show":    { "title": "Severance", "year": 2022, "ids": { "imdb": "tt11280740" } },
    "episode": { "season": 2, "number": 1 }
  }'

# 3. Пользователь досмотрел — отмечаем просмотр
curl https://myshows.me/scrobble/stop \
  -H "Authorization: Bearer $MYSHOWS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "progress": 92.0,
    "source_app": "my-player",
    "show":    { "title": "Severance", "year": 2022, "ids": { "imdb": "tt11280740" } },
    "episode": { "season": 2, "number": 1 }
  }'

Всё. Эпизод отмечен просмотренным в профиле пользователя.

Аутентификация

Каждый запрос требует заголовка с персональным токеном пользователя:

http
Authorization: Bearer <token>

Токен пользователь берёт сам на странице профиля и вставляет в ваше приложение. Токен привязан к аккаунту и не истекает по времени.

Требования к обработке токена

  • Только ASCII. Проверяйте это перед отправкой — так вы поймаете случай, когда пользователь скопировал текст с кириллическими символами, и покажете понятную ошибку вместо невнятного сбоя транспорта.
  • Не логируйте токен и не показывайте его в интерфейсе после сохранения.
  • В клиент-серверных приложениях держите токен на своей стороне, не отдавайте в браузер.
Уточнить на бэкенде

Выдаются ли токены через OAuth или PIN-флоу для сторонних приложений, или единственный путь — ручное копирование из профиля. От этого зависит, нужен ли раздел «Регистрация приложения».

Отдельно: основной API MyShows ходит с заголовком Authorization2, а скробблер — с обычным Authorization. Если на scrobble-эндпоинтах действует то же правило, что и на JSON-RPC, документация врёт.

Как работает скробблинг

Три эндпоинта описывают жизненный цикл одного просмотра.

1
POST /start
Пользователь начал смотреть — MyShows открывает сессию просмотра.
2
POST /pause
Пользователь продолжает или встал на паузу — сессия обновляет позицию. Повторяется столько раз, сколько нужно.
✓
POST /stop
Пользователь досмотрел — сессия закрывается и просмотр отмечается в профиле.

Ключевое: просмотр засчитывается на /stop, и только если progress достаточно высок.

Порог отметки

Считайте просмотр состоявшимся начиная с 80% — это значение по умолчанию в референс-клиенте, и оно совпадает с порогом Trakt и Simkl. Разумный диапазон для пользовательской настройки — 50–95%. Если пользователь бросил просмотр раньше порога, /stop слать не нужно вовсе: сессия закроется сама.

Рекомендуемый цикл

  1. Начало воспроизведения → /start с текущим прогрессом.
  2. Дальше раз в 10–30 секунд → /pause с обновлённым прогрессом. Не шлите запрос, если прогресс не сдвинулся с прошлого раза. При перемотке и паузе шлите /pause сразу, вне расписания.
  3. Прогресс перешёл порог → /stop. Дальше по этой сессии не шлите ничего.
  4. Воспроизведение прервано до порога → не шлите ничего.
Сетевой сбой

Если /stop не прошёл, не считайте сессию закрытой. Продолжайте слать /pause и попробуйте /stop на следующем тике — так обрыв связи не съедает отметку.

Эндпоинты

Базовый URL: https://myshows.me/scrobble

GET/check

Проверяет токен. Вызывайте при вводе токена пользователем, чтобы сразу показать, принят он или нет.

Уточнить на бэкенде

Что именно возвращает /check в теле ответа. Референс-клиент смотрит только на HTTP-статус. Если там есть логин или ID — это стоит задокументировать, приложения смогут показать «вы вошли как …».

POST/start

Открывает сессию просмотра.

POST/pause

Обновляет позицию в открытой сессии. Тело то же, меняется только progress.

POST/stop

Закрывает сессию. Если progress выше порога, просмотр отмечается в профиле.

Все три принимают одинаковое тело и возвращают одинаковый объект ответа.

Аниме

Аниме — единственная категория, где номер эпизода неоднозначен сам по себе, поэтому правил для неё чуть больше.

Какие идентификаторы слать

Кроме общих ключей есть пять аниме-специфичных: anidb, anilist, kitsu, mal, shikimori. Если знаете хоть один — отправляйте. Для аниме они надёжнее tmdb и tvdb, потому что не зависят от того, как каталог нарезал сериал на сезоны.

Если знаете и tmdb, и tvdb — отправляйте оба. На сплит-кур тайтлах (Attack on Titan, Solo Leveling) границы сезонов у этих двух каталогов расходятся, и по одному ID невозможно понять, о каком куске сериала речь.

Уточнить на бэкенде

Какой идентификатор выигрывает при конфликте TMDB и TVDB. У Simkl маппинг построен на координатах TVDB, и правило зафиксировано явно. Нам нужно такое же: без него сплит-кур аниме уедет не в тот тайтл — молча.

Абсолютная нумерация

У аниме-релизов сезон часто просто отсутствует: в имени файла стоит сквозной номер — Frieren - 12 [1080p].mkv. В этом случае отправляйте episode.number без episode.season. Это допустимо, поле необязательное.

Главное правило

Не пересчитывайте абсолютный номер в пару «сезон + эпизод» на своей стороне. Для этого нужна та же таблица маппинга, что и у каталога, а разъедется она незаметно и задним числом. Отправьте то, что знаете, и оставьте сопоставление серверу.

Референс-клиент так и устроен: парсер имени файла достаёт сквозной номер и оставляет сезон пустым, а конвертер просто не кладёт поле в payload.

Спецвыпуски, OVA и ONA

Референс-клиент их не различает: OVA уходит эпизодом родительского сериала с тем номером, который дал источник.

Уточнить на бэкенде

Заведены ли OVA, ONA и спецвыпуски отдельными записями каталога — как у Simkl, где для этого есть поле anime_type — или это эпизоды родительского сериала. Если отдельными, то часть отметок сейчас попадает мимо, и никакого сигнала об этом клиент не получает. Ответ определяет, нужно ли заводить в DTO поле типа записи.

Уточнить на бэкенде

Что возвращает /stop, когда прогресс ниже порога. У Trakt в этом случае приходит 200 с action, отличным от scrobble — то есть по HTTP-статусу засчитанный просмотр от незасчитанного не отличить. Если у нас так же, здесь нужен явный абзац «как понять, что просмотр засчитан»: это первое, что спросит интегратор.

Ошибки

Уточнить на бэкенде

Полная таблица кодов и формат тела ошибки. Ниже — то, что видно со стороны клиента. Это не спецификация.

КодЗначение
401Токен неверен или отозван — попросите пользователя обновить его

Повторы. На сетевых ошибках и 5xx делайте до трёх попыток с экспоненциальной паузой (1 с, 2 с). Таймаут запроса — 5 секунд. На 4xx не повторяйте.

Правила использования

Уточнить на бэкенде

Rate limits в запросах за единицу времени, поведение при превышении (429 и Retry-After?), политика для приложений с большой базой пользователей. У Simkl это первый экран страницы правил — цифра нужна.

Пока лимиты не опубликованы, придерживайтесь этих правил — они удерживают трафик на разумном уровне сами по себе.

  • Не чаще одного /pause в 10 секунд на активную сессию.
  • Пропускайте тики без движения. Если прогресс не изменился с прошлой отправки, запрос не нужен.
  • Указывайте source_app и app_version. Это единственный способ для MyShows отличить трафик вашего приложения от чужого — в том числе когда нужно разобраться с проблемой, а не заблокировать.
  • Не полируйте прогресс. Отправляйте то, что реально говорит плеер.

Совместимость с Trakt и Simkl

Формат специально сделан надмножеством scrobble-API Trakt и Simkl: оба игнорируют неизвестные поля, поэтому один payload уходит во все три сервиса без изменений. Если вы уже интегрированы с Trakt или Simkl, поддержка MyShows — это новый базовый URL и токен, а не новый маппинг.

ПолеMyShowsTraktSimkl
progress, movie, show, episode✓✓✓
app_version, app_date✓✓✓
ids.imdb, tmdb, tvdb, slug✓✓✓
ids.anidb, mal, netflix, hulu✓—✓

Известное расхождение типов

ids.tmdb у Trakt объявлен как number, у Simkl — как string. На практике оба принимают строку, поэтому в этом API тип — string.

Проверить экспериментом

У Simkl для аниме два раздельных конверта: show + {season, number} для ID каталогов TMDB/TVDB и anime + {number} для аниме-нативных ID. Наш payload для аниме берёт конверт от первого варианта, а нумерацию от второго — show и номер без сезона. Такой комбинации в документации Simkl нет.

То есть обещание «один payload на три сервиса» проверено не везде и на аниме держится слабее всего. Либо проверяем и правим текст выше, либо оговариваем исключение явно.

Уточнить на бэкенде

Есть ли на сервере пакетный импорт истории. В DTO объявлены SyncHistoryRequest и SyncHistoryResponse, но референс-клиент их не вызывает. Если эндпоинта нет — типы стоит убрать из DTO, чтобы они не выглядели поддержанными. Если есть — сюда нужен раздел «Импорт истории».
